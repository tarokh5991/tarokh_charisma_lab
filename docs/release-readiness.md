# چک‌لیست آمادگی انتشار

این چک‌لیست پیش از بازکردن دسترسی عمومی یا آغاز بتای محدود استفاده می‌شود. هر مورد باید توسط مسئول مشخص‌شده تأیید شود.

## ۱. نسخه و انتشار

- [ ] شاخهٔ `main` شامل نسخهٔ تأییدشده است و workflow انتشار GitHub Pages با موفقیت تمام شده است.
- [ ] بررسی‌های type-check، فرمت و تست قراردادی در اجرای انتشار سبز هستند.
- [ ] نشانی رسمی محصول، عنوان صفحه و مسیرهای اصلی پس از انتشار بررسی شده‌اند.

## ۲. Supabase و دسترسی‌ها

- [ ] همهٔ migrationها به‌ترتیب روی پروژهٔ مقصد اعمال شده‌اند.
- [ ] متغیرهای `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` فقط در secrets انتشار قرار دارند.
- [ ] نشانی رسمی محصول در تنظیمات redirect احراز هویت Supabase ثبت شده است.
- [ ] قالب OTP ایمیل شامل `{{ .Token }}` است و SMTP production تأیید شده است.
- [ ] Edge Function مربی منتشر شده و secretهای سمت سرور آن فقط در تنظیمات امن Supabase قرار دارند.
- [ ] حساب مدیر تعیین‌شده می‌تواند پنل مدیریت را ببیند؛ حساب عادی به آن دسترسی ندارد.

## ۳. تست مسیر اصلی با حساب آزمایشی

- [ ] ثبت‌نام و ورود دوباره با OTP.
- [ ] تکمیل ارزیابی و نمایش پیشنهاد CLEAR در داشبورد.
- [ ] فعال‌سازی آزمایشی یک پلن و کنترل محدودیت دسترسی پلن.
- [ ] بازکردن درس، ثبت مطالعه و تمرین، و مشاهدهٔ پیشرفت.
- [ ] ارسال یک پیام به مربی AI و مشاهدهٔ سهمیهٔ باقی‌مانده.
- [ ] ثبت یک بازخورد بتا و مشاهدهٔ آن در پنل مدیریت.
- [ ] خروج از حساب و حذف حساب آزمایشی پس از پایان بررسی.

## ۴. عملیات و بازیابی

- [ ] جدیدترین بکاپ سالم گرفته، اعتبارسنجی و خارج از مخزن ذخیره شده است.
- [ ] مسیر پشتیبانی رسمی و مسئول رسیدگی به خطاها مشخص هستند.
- [ ] روند بکاپ و بازیابی در `docs/supabase-backup-recovery.md` برای تیم قابل دسترس است.
- [ ] پیش از هر migration مهم، بکاپ جدید گرفته می‌شود.

## معیار تصمیم انتشار

انتشار زمانی مجاز است که هیچ مورد «فوری» باز نباشد: ناتوانی در ورود، از دست‌رفتن داده، دسترسی نادرست به پلن، مشکل مرتبط با پرداخت یا افشای داده. موارد با اولویت بالا باید راه‌حل یا مسیر جایگزین روشن داشته باشند.
